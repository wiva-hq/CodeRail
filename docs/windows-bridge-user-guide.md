# Windows Bridge 本机使用说明（验收候选）

当前 Windows x64 包仍为开发验收版本，尚未通过完整 Gate 3/4，也没有公开 Windows 下载或签名发布。以下命令针对已获得并核对 SHA256 的编译 EXE；不能把本文当作已上线的一键安装入口。

## 当前用户安装与配对

在自己的开发用户会话打开 PowerShell，执行编译包的完整路径：

```powershell
& 'C:\path\to\coderail-windows-x64.exe' install
```

按输出的安装路径执行 `pair https://你的站点`。PowerShell 调用带空格的路径需使用 `& '完整路径'`，不要直接复制 CMD 的引号调用形式。安装只写入当前用户目录、HKCU 启动项和当前用户 PATH，不要求管理员。首次安装成功后才配对，后台使用该用户的 Codex 登录态、Git/SSH 与开发环境。不要用另一个 Windows 账户或管理员账户代替日常开发用户安装；不会替其他用户共享认证。

PATH 通知可能无法刷新已经打开的终端，此时直接使用输出的 EXE 完整路径，或新开终端。后台的登录启动已注册；真实重新登录的验收仍未完成。`status` 检查运行情况；`status --json` 提供结构化进程树、内存和监听端口采样。working set 是逐进程相加，可能重复计算共享页面。

## 网络与防火墙

Bridge 主动连接配对站点的 HTTPS/WebSocket，一般是 TCP 443；自建站点使用其他端口时需允许其实际端口。终端、文件与开发预览经现有连接转发，Bridge 不要求公网入站端口，也不自动添加防火墙规则或关闭防火墙。开发服务器优先只监听 `127.0.0.1`；不需要为远程预览把它绑定到所有网卡。

如果 Windows 或企业防护软件弹出联网提示，核对可执行文件路径和校验和，仅允许实际站点所需的出站连接；无需为了 Bridge 开放公共网络入站。开发服务器自身的防火墙提示与 Bridge 转发是不同的联网请求。企业限制或自定义出站规则需由用户/管理员按组织政策处理。

支持继承 HTTP_PROXY/HTTPS_PROXY/NO_PROXY，以及当前用户的手工系统代理；PAC/WPAD/SOCKS 与系统代理回退的 CIDR 匹配尚不支持。代理密码和 Codex 凭据不要写入报告或公开日志。连接失败先查看 `status` 和 `logs`，核对站点地址、TLS、代理及网络；不要通过禁用防火墙排障。

## 日常维护与卸载

`logs` 查看最近日志，`logs -f` 持续跟随；Windows supervisor 的自动轮转候选保留 `bridge.log` 和 `bridge.log.1`，每个最多 10 MiB。快速轮转时跟随读取不保证回放全部中间日志；它是诊断尾随，不是审计归档。日志损坏、锁定或被替换为链接会明确失败，避免越界写入。

`restart` 会清理旧 Bridge Job 再启动。`update` 从配对站点读取 Windows Manifest；目前真实 Cloudflare Windows Manifest 尚待交付，本地 fixture 更新通过不代表该线上地址已可用。健康检查失败会回滚；未知 helper ABI 会拒绝更新。

当前 install 不覆盖已有安装，update 也不替换运行中的 helper。保留配对的 helper 修复仍在独立 PoC，尚无正式命令；不要为更新 helper 直接卸载。自定义长安装目录还可能触发 Run 启动命令长度限制，文件系统长路径验证不能替代安装器验证。

`uninstall` 先撤回自有启动项和 PATH，再安排外部清理 actor 等待 CLI 退出、清空服务树并删除自有安装目录。输出“scheduled”不代表文件已经删完；目录仍存在时检查输出指向的 `cleanup-error-*.txt`。未知文件、链接或占用可能使清理保留目录并报错，请不要对未经核实的路径使用递归强删。

另一标准用户、真实重登、休眠唤醒、Wi-Fi 切换与净室卸载仍需单独完成；不会自动重启、休眠机器或启用 Sandbox。
